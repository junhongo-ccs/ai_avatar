# Dify 環境の引っ越し手順

Difyアプリ `ai-avatar-poc` を、個人の無料版（Dify Cloud Sandbox）から会社のアカウントへ移すための手順です（2026-10 作成）。

## 全体の流れ

1. 旧環境からDSL（yml）をエクスポートする
2. 新環境でモデルのプラグインを入れ、APIキーを登録する
3. DSLをインポートする
4. ナレッジを2つ作り直し、ナレッジ検索ノードで選び直す
5. アプリを公開してAPIキーを発行し、`.env` とRenderの環境変数を書き換える
6. 動作を確認する

## 1. DSLのエクスポート

スタジオで `ai-avatar-poc` のメニューから「DSLをエクスポート」を選びます。

エクスポート済みのDSLは [ai-avatar-poc.yml](ai-avatar-poc.yml) です（2026-10-13取得）。環境変数や秘密情報は含まれていません。プロンプトの控えは [prompt.md](prompt.md) にあります。

DSLで移るもの：チャットフローの構成、プロンプト、変数、開始メッセージ、各機能の設定、ナレッジ検索ノードの設定（ウェイト 意味0.7／キーワード0.3、トップK 5、Rerankなし）。

DSLで移らないもの：

| 項目 | 対応 |
|---|---|
| モデルプロバイダーのAPIキー | 手順2で登録する |
| プラグイン本体 | 手順2で入れる（DSLには一覧だけが入る） |
| ナレッジ | 手順4で作り直す |
| 秘密の環境変数 | エクスポート時に「含める」を選ばなければ空になる |
| 会話ログ・注釈 | 移らない。注釈を使っている場合はCSVで一括エクスポート／インポートする |
| アプリのAPIキー | 新しく発行される（手順5） |

## 2. プラグインとモデルの準備

Dify 1.0以降は、OpenAIなどのモデルプロバイダーもプラグインです。新環境のワークスペースで、LLMノードと埋め込みに使っているモデルのプラグインを入れ、会社のAPIキーを登録します。

- 必要なプラグインは `langgenius/openai`（DSL作成時はバージョン1.0.6）の1つだけです
- LLMノードは `gpt-5.4`、埋め込みモデルは `text-embedding-3-large` を使っています（どちらもOpenAI）
- 会社のワークスペースでは、プラグインを入れられるのが管理者だけのことがあります。その場合は管理者に依頼します

## 3. DSLのインポート

新環境のスタジオで「DSLファイルをインポート」を選びます。足りないプラグインがあればインストールを求められます。

インポート後、LLMノードを開いてモデルが正しく選ばれているか確認します。同じモデルが使えない場合は選び直します。

新環境が自前でホストしているDifyでバージョンが古い場合は、DSLのバージョン違いの警告が出ることがあります。

## 4. ナレッジの作り直し

ナレッジは移せないので、リポジトリの [rag/](rag/) のファイルから作り直します。登録するファイルと推奨設定は [rag/README.md](rag/README.md) を参照してください。

| ナレッジ | ファイル | チャンク識別子 | 検索設定 |
|---|---|---|---|
| recruit_ccs_refined | `recruit_ccs_refined/` の2ファイル | `---` | ベクトル検索 |
| ccs_solutions | `ccs_solutions/` の `00`〜`12`（13ファイル） | `## ` | ハイブリッド検索 |

採用ナレッジの名前は `recruit_ccs_refined` のままにしてください。プロンプトがこの名前で指定しています。ソリューション資料のナレッジは、旧環境の「00_overview.md...」から `ccs_solutions` に名前を変えました。

作り終えたら、チャットフローのナレッジ検索ノードを開き、新しいナレッジを2つとも選び直します（旧環境のナレッジIDを参照したままになっているため）。

## 5. APIキーと環境変数の更新

アプリを公開し、「APIアクセス」で新しいAPIキーを発行します。

| 変数 | ローカル（`backend/.env`） | Render |
|---|---|---|
| `DIFY_API_KEY` | 新しいキーに変更 | 新しいキーに変更 |
| `DIFY_API_URL` | `https://dify.solccs.net/v1` | 同左 |

APIキーはサーバー側だけに置きます。ブラウザは自前サーバーの `/api/chat` を呼び、サーバーがキーを付けてDifyへ中継します。`VITE_` を付けた変数はビルド時に画面のJavaScriptへ埋め込まれて誰でも見られるので、キーには使いません。

社内Difyの「APIアクセス」画面ではベースURLが `http://` と表示されますが、`https://` が正しい入口です（httpはhttpsへ転送される）。

## 6. 動作確認

- `/chat-messages` を数回呼び、`answer` が `{"face":"...","messages":["...","..."]}` 形式のJSONだけで返ること（モデルが変わると形式が崩れやすい）
- 「荒谷さんの好きな音楽は？」に、敬称なしの「荒谷」で答えること
- 採用の質問（例：勤務地、在宅勤務率）でQ&Aに沿った回答になること
- ソリューションの質問（例：WinActorとは）で資料に沿った回答になること
- 従業員数を聞くと、最新の値（785名、2026年4月1日現在）で答えること
- 画面のステータス表示が `mode: dify` / `status: connected` になること

## 旧環境について

- 無料版では、しばらく使わないとナレッジの文書が自動で無効になります。2026-10-13時点で、旧環境の全文書が無効になっていました
- 旧環境のナレッジには、`01_overview.md` の古い版（従業員771名）が入っています。正しいのはリポジトリの版です
- 新環境で動作確認ができたら、旧環境のアプリは残しておくか削除するかを決めます
